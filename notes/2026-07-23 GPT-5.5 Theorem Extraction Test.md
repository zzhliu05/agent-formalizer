# GPT-5.5 Theorem Extraction Test

## Goal

Evaluate the second internal stage of Agent 1 on a larger private sample from the same Folland scan used for the Markdown-only smoke test. Gemini remains a transcription-only model; theorem and proof extraction is performed separately by the ShanghaiTech GPT-5.5 endpoint.

## Scope

- Requested PDF range: pages 19–30, twelve pages.
- Successfully transcribed and extracted range: pages 19–27, nine unique pages in four three-page chunks with one-page overlap.
- The one-shot twelve-page Gemini request was blocked by its copyright/recitation filter. The split run produced four chunks before the pages 27–29 request was also blocked, so pages 28–30 were not claimed as tested.
- All textbook-derived Markdown and theorem packages remain under `outputs/private-tests/`, which is ignored by Git.

## Extraction contract

- Request model: `GPT-5.5`.
- Deployment label: `east-US-2-gpt-5.5`.
- Endpoint behavior verified as Bearer-authenticated, Chat Completions-compatible structured output using `max_completion_tokens`.
- Resolved model returned by the successful calls: `gpt-5.5-2026-04-24`.
- Every statement, proof, proof step, omission marker, and context quotation must match the OCR Markdown after whitespace and Markdown-emphasis normalization.
- A proof-step partition that changes or drops text is replaced with one exhaustive verbatim evidence step and marked in `uncertainties`.
- A theorem-like candidate whose label is absent from the source is rejected and recorded rather than written.

## Result

- Four successful GPT-5.5 requests.
- 21 unique numbered records, covering every label from 0.4 through 0.24 without gaps.
- Proof status: 16 `complete`, 3 `partial`, and 2 `by_reference`.
- The five non-complete records all carry an explicit omission flag, reason, marker, and note.
- 26 prerequisite-context items.
- Two proof-step partitions were conservatively collapsed to one exhaustive verbatim step.
- Nine theorems have multiple immutable attempts because overlap or earlier failed runs produced additional evidence variants; `latest.json` identifies the audited record.
- Provider usage across the four successful requests: 19,439 input tokens, 30,745 completion tokens, 50,184 total tokens.
- All 21 audited `latest.json` hashes match their referenced `theorem.json`.
- The package test suite passes 14 tests.

## Interpretation

The test demonstrates evidence-preserving extraction and explicit handling of proofs whose printed details are abbreviated or delegated. It does not establish mathematical equivalence, OCR perfection, or readiness for Lean formalization. Agent 3 must still compare the extracted source meaning against later Lean statements, and a human-verified extraction evaluation set is needed before chapter-scale ingestion.
